# Vulnerability Tracker API — Чек-лист

## Основные эндпоинты

- [ ] **1. Добавление записи об уязвимости**
  - [ ] Принимает название и уровень критичности
  - [ ] Автоматически фиксирует дату добавления
  - [ ] Возвращает идентификатор созданной записи
- [ ] **2. Получение информации об уязвимости по ID**
  - [ ] Возвращает полную информацию об уязвимости
  - [ ] Корректный ответ при отсутствии записи (404)
- [ ] **3. Запуск фоновой задачи сканирования**
  - [ ] Принимает ссылку на репозиторий (например, GitLab)
  - [ ] Сервис генерирует идентификатор задачи
  - [ ] Возвращает ID задачи сканирования
  - [ ] Сканирование выполняется асинхронно в фоне
- [ ] **4. Получение статуса задачи сканирования по ID**
  - [ ] Возвращает состояние: выполняется / завершена / ошибка
  - [ ] Возвращает время последнего изменения статуса
  - [ ] Возвращает результат сканирования, если задача завершена

## Обязательные требования

- [ ] Сервис без постоянного хранилища (in-memory, каждый запуск — чистый лист)
- [ ] Логирование запросов
- [ ] Обработка ошибок
- [ ] Unit-тесты
- [ ] Документация: как запускать сервис, где хранятся файлы, полезная информация по запуску

## Задачи со звёздочкой (приоритет)

- [ ] **1. Ограничение параллельного сканирования**
  - [ ] Настраиваемый лимит одновременных сканирований
  - [ ] Остальные запуски ставятся в очередь
  - [ ] Статус «в очереди» для ожидающих задач
- [ ] **2. Отмена сканирования**
  - [ ] Эндпоинт возвращает идентификатор, время и успешность отмены
  - [ ] Отмена сканирования, стоящего в очереди
  - [ ] Прерывание уже запущенного сканирования

## Примечания к реализации

- **«Без постоянного хранилища»** означает, что БД не нужна: сущности и статусы держат в памяти (`ConcurrentDictionary` + `lock` или `Channel`), а PostgreSQL/EF в решение можно не тащить. Если Postgres остаётся — это отступление от условия, стоит явно указать в документации.
- **«Время последнего изменения статуса»** — поле `UpdatedAt` в модели задачи, обновляется при каждом переходе статуса и возвращается в ответе эндпоинта 4.
- **Отмена запущенного сканирования** — через `CancellationToken`: свой `CancellationTokenSource` на каждую задачу (словарь по ID), при отмене — `cts.Cancel()`, воркер проверяет `ct.IsCancellationRequested` и корректно прерывается со статусом «отменена».
